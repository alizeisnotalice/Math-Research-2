# 数值队列与已知公平控制的条件数回归

MacBook degree60原生Metal队列的24目标已结束，协调器与原生进程均已退出。父按精确range/handoff/回执/SHA核对75片、159,744批、20,937,965,568个数值mask及638,976保存样本。这里仅审覆盖和保存的数值元数据，尚未独立重构所有保存样本，不提供数学排除或原题反例。原名义task0控制先生成58次乘积再补x60，不能称为所标称乘积的公平控制。

新degree62输入由77次确定性抽样选24目标，53个因原生group容量而拒绝的抽样明确记录在运行输入，不当数学排除。控制目标为严格二元的(1+x²)(1+x⁶⁰)。31个复共轭组满足当前内核容量，24目标总计25,769,803,776个数值mask。新队列已实际启动，13进程CPU语义任务与该GPU队列并行；目前不声明整队列完成。

公平控制的smoke发现旧逐组顺序浮点卷积发生严重抵消：CPU分数约0.00279768、目标残差约0.00537701，而GPU float32评分约1.84e−6。以相反斜率配对并平衡乘法树后，CPU分数／残差约7.24e−10。`verify_conditioning.py`在同一冻结根输入上独立复现这一差别，并以整数卷积检查控制目标确为公平。它说明该控制上的重构稳定性，不是一般误差保证。

新控制器同时保留GPU近阈值及目标乘积不一致的unknown标记，不能只凭失真的CPU分数把近例当作负例。两次smoke均只作smoke、不记生产覆盖；新生产每2^28 masks退出一个原生进程释放内存，按严格半开区间handoff续算。浮点根、数值残差小和未命中均不是精确证书。
