六点的两个程序扩展位存储至128位，并保留位集并集法与直接逐和计数两种独立实现。最初源码生成器插错 include 前的插入点导致编译失败，修正后才开始数学计算。60组对照约412.6万个原始对，与标准库 Python 的原逐对实现一致，测试覆盖跨64位和总次126边界。六点第62／63层与第64／65层分别完整复核2,319、3,103片。本机10进程两次生产耗时61.74、90.14秒，独立耗时238.81、567.45秒。

九点层沿用第56轮已验证的64位两实现，MacBook13进程生产70.02秒，独立1434.10秒，8,142片逐条相同。257个初筛未判由248份直接对角证书及9份有理恒等式严格排除。大批量计算的主管与全部工作进程已退出。搬回账本后从待提交目录逐项复核了所有剩余证书。

使用第56轮的比较器重新生成覆盖摘要，例如：

    python3 ../056-support-compact/compare_complete.py six64-65/production six64-65/independent --totals 64 65 --cap 6 --out /Volumes/data/CodexTemp/T2/a30-six65-check.json
    python3 ../056-support-compact/compare_complete.py nine39-40/production nine39-40/independent --totals 39 40 --cap 9 --out /Volumes/data/CodexTemp/T2/a30-nine40-check.json
    python3 nine39-40/verify_residual.py

六点新源码位于 wide-engines，分别用 Clang C++20 -O3 编译两个 support_bitset 后，可调用各自的 run_bitset.py 从头独立枚举。详细选项与规范化依据见[第56轮说明](../056-support-compact/README.md)。
