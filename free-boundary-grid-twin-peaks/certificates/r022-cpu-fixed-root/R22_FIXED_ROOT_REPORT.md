# r22：一峰固定根 normalizer（有限核验与 n=11 探索）

## 对象与核

对根 (r)，`Z` 估计

\[
h_r=\#\{\text{标号一峰全序：最高标号峰（首字母）为 }r\}.
\]

这是标号序数目，而不是 (h_r/N!\)。程序按标号由高到低固定首字母后，只从 rank 2 开始相继
抽取可接邻点；因而每粒子每副本恰有 (PL(N-2)) 个 MH 提案。原
swap/replace 提案在有序无重复词上对称；限制为首字母仍是 `r` 且前缀有效的
端点接受，其余留在原状态，故限制核仍对称并保留固定根有效前缀的均匀律。
这不是一般不可约性或混合时间的证明。

`verify_fixed_root.py` 的 n=3 完整穷举逐根、逐前缀深度确认：`allowed`
产生的支持集正确、端点拒绝转移矩阵逐项对称、列和等于行和。独立 Python
子集 DP 与 C++ exact 逐根重合：总一峰计数为 n=3 的 29,568、n=4 的
35,704,394,880。

n=3 (`P=257,R=128`) 与 n=4 (`P=4096,R=64`) 的每根、每
`L=0,4,16` 共 75 个校准都通过副本、种子、`dead=0`、提案数核验；相对
精确值的最大绝对有限样本误差为 1.074%。这只是实施校准。

\[
 h_{r'}/h_r\le C\frac{n^2}{(k+1)^2},\qquad
 h_{r'}/h_r\le\left(\frac{n-1-k}{k+1}\right)^2.
\]

## 误选根记录、资源和退出

初版运行在 (2,2) 后把编号误写为 23、34、35、45、46、56；它们是有效但
**离阶梯**的独立输出，明确记录于 `OFF_STAIR_NOTICE.md`，不进入
`n11-root-summary.json` 或上述表。正确缺失六根以新的种子补跑。

首批（含五个可用根及六个离阶梯根）耗时 1791.05 wall seconds；正确补跑六根
耗时 887.84 wall seconds；二者均 0 swaps、最大 RSS 约 217 MB / 213 MB。
这不是干净可加的“正确十一根总用时”，因此没有虚报单一资源数。所有
`fixed_root_smc` 子进程在汇总时已退出。
