# r046 有限门检与性能摘要

本文件记录的是 r046 最终源码的**实际有限运行**，而不是关于任意输入、任意编译器、任意机器或原 twin-peaks 猜想的证明。

## 正确性门检

最终源 psi_search_undo.cpp 与冻结 r040 源在相同编译设置、相同初态、相同种子和相同提案数下逐字节比较最终输出。每个 r046 运行再由独立的 Fraction 验证器检查词为合法的一峰词，并精确重算 Psi。

搜索器的 audit=1 不会对非法交换候选调用 rebuild()：非法候选由 swap_try 检出后立即 rollback。对每个 swap_try 返回 true 的合法候选，代码在接受/拒绝决定前从头 rebuild()，逐项比较 a,pos,l,b,sole 与 Psi；循环结束还会分别重建当前 State 和 best State。因此下述门检覆盖了合法候选的逐项审计、接受/拒绝路径的输出一致性及终态独立验证，但不应表述为“每一提案（含非法候选）均从头重建”。

实际已完成的 24 例均 exit 0、验证通过、且与 r040 输出逐字节相同：

* n=3、4：BFS（中心 root），row（root 0），ring（root 0）；每种 seed 1、2、3，共 18 例；
* n=16、32、64：BFS（中心 root）和 ring（root 0），seed 1，共 6 例。

每例为 10,000 次提案。有限的种子、尺寸、初态和提案轨迹只支持实现交叉核验；不等同于全输入等价性证明。

## 性能比较

在 Mac mini / Apple M6 / 12 CPU 核 / 16 GiB 统一内存上，以单进程单链、相同 seed 20261117、100,000 次提案、审计间隔 1000 实测。机器同时有其他负载，故只把 /usr/bin/time -l 的 **user CPU 秒** 用作同机比较；wall time、峰值 RSS 和跨机器结果均不可外推。

| case | r040 user CPU s | r046 user CPU s | r040 peak bytes | r046 peak bytes |
| --- | ---: | ---: | ---: | ---: |
| n=32, ring root 0 | 2.21 | 0.08 | 1,769,856 | 1,933,696 |
| n=32, BFS center | 2.28 | 0.09 | 1,786,240 | 1,966,464 |
| n=64, ring root 0 | 8.53 | 0.08 | 2,834,840 | 2,736,536 |
| n=64, BFS center | 8.67 | 0.11 | 2,769,304 | 2,671,000 |

这些数值显示在此设置下取消每提案的全 State 复制后，CPU 时间显著下降；并不构成生产吞吐、内存上界或搜索质量的普遍保证。
