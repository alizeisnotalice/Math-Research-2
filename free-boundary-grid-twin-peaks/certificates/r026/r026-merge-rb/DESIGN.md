# r026：首次合并 Rao--Blackwell 终端统计设计

对固定的完整首次合并纤维，令合并前两个分支的大小为 \(a,b\)，\(q=a+b\)，并令

\[
m(a,b)=\frac{q(q-1)}{2ab}.
\]

既有严格纤维恒等式的条件是：固定两侧内部词和合并后无新出生后缀，但对 AB/BA
方向及余下交错取均匀平均；根交换不变且交错不变的 \(H\) 才满足

\[
\mathbb E_{\tau=2}[L H\mid\mathcal D]=m(a,b)H.
\]

这里可取 \(H=1,d^2,F_0,G_0\)。这不是逐词公式 \(L=m\)，也不自动说明有限
SMC 的方差降低。它可作为理想目标律的 Rao--Blackwell 终端函数，未来有限 SMC
只能将它作为另一项诊断统计。

## 每粒子在线重建

在 terminal \(N-1\) prefix 后补入唯一未出现顶点，顺序扫描完整 \(N\) 点：第一根
置入集合 A，第二根置入集合 B。其后每个点检查是否邻接 A/B：只触及一侧就加入该
侧；首次同时触及两侧时记录当前 \(a=|A|\)、\(b=|B|\)、\(q=a+b\)，停止扫描。
对于合法 \(\tau=2\) 完整词，合并前没有第三个连通分支；若未找到或触及异常，应
设置严格 bad flag。算法仍扫描最后一点，作为全词核验及推广到一般图的健壮处理；
但本题方格 (nge2) 无割点，故首次合并不可能恰在最后遗漏点：否则合并前的
两个分支会使删去该点后的方格不连通。

GPU 实现可为每粒子暂存两组 1024-bit 集合（各 32 个 UInt32），合计 256 bytes/粒子；
在 \(P=131072\) 时约 32 MiB。在终端 kernel 输出 \(a,b,r_1,r_2\) 四个 UInt16
（8 bytes/粒子，约 1 MiB）。主机据此计算分数 \(m\) 与 \(mH\)；可使用 Double
作有限诊断，但不能把浮点和视为严格分数认证。现有整数 L 群组字段应保留并与新的
非整数 m 统计并列，不能以 m 伪装为整数群组或替换锁定 L 字段。

新 consistency cone 不是独立的采样精度证据：逐粒子
(m,d/[2(d-1)]geq 1)，所以任何带非负样本权重的 (m)-RB 重构都会自动
通过相应 guard。它只检查该结构是否被实现；有限 SMC 的 (Z) 集中、混合和方差
问题仍未得到认证。

输出还应保存 source hash、是否包含终端补点、每粒子 \(a,b,r_1,r_2\) payload 的
hash，以及 `bad` 计数。该 GPU terminal kernel 已由本目录有限 trace 结合独立
CPU 重放核验；没有启动 GPU 生产批。

## 实际 CPU 原型结果

`audit_merge_rao_blackwell.py` 用 `Fraction` 枚举 \(3\times3\) 的全部 \(9!\)
个标号，并按完整 fixed-fibre key 检查 32128 个首次合并纤维。对
\(H=1,d^2,F_0,G_0\)，全体双峰总和、\(\tau=2\) 的 \(LH\) 总和和 \(mH\) 总和
逐纤维相等，均给出

\[
(A_2,D,F,G)=(143808,633600,1620480,-456960).
\]

同一枚举中 67200 条 \(\tau=2\) 词满足 \(L\ne m\)，明确排除逐词替换的误读。
已保存 r025 的 17 粒子 trace 也以完整末点重建检查：其 \(L\)-总和为
\((26,108,280,-76)\)，相应的 \(m\)-加权和为
\((239/8,2777/24,1871/6,-151/2)\)。它们不同完全正常，因为该有限粒子集不是
完整 fibre 条件平均；不得把这一差异说成理论反例或方差比较。

原型在 n=3 的完整枚举及该 trace 中未出现“最后遗漏点就是首次合并”；对本题方格
这是由无割点性推出的必然事实，而非有限无事件。终端扫描仍明确补入该点，以支持
全词核验及一般图的同一实现。
