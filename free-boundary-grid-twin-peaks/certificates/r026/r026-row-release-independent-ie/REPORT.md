## 通用 boundary-completion IE 定理与本次实例

设有限简单图 \(G=(V,E)\)，已揭示的连通前缀为 \(S\)，并令
\(B=N(S)\setminus S\)、\(U=V\setminus(S\cup N(S))\)。把完成词反向看成对
\(V\setminus S\) 的严格标号。一个正向不合法的首次揭示点对应反向标号中的局部峰；
边界 \(B\) 可以是峰，\(U\) 中的峰必须排除。

对独立集 \(I\subseteq U\)，令 \(C_S(I)\) 为所有 \(I\) 中顶点都是局部峰的标号数。
它满足

\[
C_S(\varnothing)=(|V|-|S|)!,\qquad
C_S(I)=\frac{\sum_{v\in I}C_S(I\setminus\{v\})}{|I\cup N(I)|}.
\]

理由是该事件只依赖 \(I\cup N(I)\) 内的相对序：其中最大元必唯一属于某个
\(v\in I\)，并且独立性保证删去该 \(v\) 后其余峰约束仍是
\(I\setminus\{v\}\) 的约束。于是容斥给出

\[
h(S)=\sum_{I\subseteq U,\ I\text{ independent}}(-1)^{|I|}C_S(I).
\]

这正是既有的通用实现 `completion_ie_selected.cpp` 中的 `build_C` 与 `F`；本轮
**不把它冒称为新算法**。它完全不同于新 native 行释放程序对残余 \(H\) 的四个
全子集数组的反向 DP，且直接计算完整方格的完成数。

对于本题，顶行前缀 \(T\) 是掩码 `0x(2^n-1)`，故 `h(T)=H_T`；前两行前缀
\(R\) 是 `0x(2^(2n)-1)`，故 `h(R)=H_R`。变量区及可被容斥选择的集合分别是：

| 完成数 | 初始前缀 | 可选峰区 |
|---|---|---|
| \(H_T\) | \(T\) | \(y\ge2\) 的 \((n-2)\times n\) 矩形 |
| \(H_R\) | \(R\) | \(y\ge3\) 的 \((n-3)\times n\) 矩形 |

## n=7 仅资源估计

`estimate_n7_independent_sets.py` 用行转移而非 C(I) 计算得到：T 的剩余 5x7
矩形有 **3,729,091** 个独立集（最大大小 18），R 的剩余 4x7 矩形有 200,798 个
（最大大小 14）。先前出现的 3,843,618 是其他 n=8 非矩形 35 点集合的数量，不能
用作这里的 5x7 预算。每个 \(C(I)\le42!\) 为 170 bit；粗略的有符号总和上界
分别为 192、188 bit。因此通用核的 U256 足够；把最坏总和放入 U192 没有安全余量。
本机没有运行 n=7。远端若运行，先 T 后 R，且每一个进程完成并回收内存后才启动下一个。

## native 行释放核的审计要点

阅读并以 n=3--5 上表交叉
`row_release_native.cpp`（本轮 native 包中的同 SHA 源）
（SHA-256 `4f0be624d70a488c9501d68fd4c2ec77f88b9556af80d385e4247204cf42ba63`）：

- 剪枝 `rnb[i] || (hnb[i]&S)` 精确等于从已保留前两行或已加入 \(H\) 邻点可生长；
  `!(hnb[i]&S)` 在该剪枝下只会发生在 \(y=2\)，恰为解析公式的 birth。
- 反向状态已有 \(p\) 个 birth、\(|S|=k\) 时，新 birth 是正向第 \(k+1\) 位的第
  \(p+1\) 个 birth，系数应为 \((k+1)+(p+1)-1=k+p+1\)。代码的
  `W[p][T] * (k+p+1)` 正是这个索引；首步单独求和时系数为 1。
- 末端 \((M+n)!/(M+p)!\) 和 \(p\le\lceil n/2\rceil\) 与纤维公式一致。
  但任意数组条目未必可达，故不能用“每项注入完成词”笼统证明界。已将 native 的
  `REPORT.md` 改为形式项界：未来 \(t\) 次 birth 与末端阶乘抵消后，每项
  \(\le(M+n)!/(M+p)!\)，至多 \((M-k)!\) 个后缀，故任意非负表项
  \(\le(M+n)!(M-k)!/(M+p)!\le(M+n)!\le30!<2^{128}\)。

这些工作只核验有限精确完成数及实现；不比较 \(H_T\) 与 \(A_1\)，不解决原双峰问题。
