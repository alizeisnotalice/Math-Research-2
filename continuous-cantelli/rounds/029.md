# 第29轮　原点饱和后的两个系数

第28轮的首项可以等于 1，此时必须比较剩余质量与误差的大小。写 ℓ=log(1/u)、f(u)=u²/(2D)，在饱和首项 D=ℓ+(log ℓ)/2+log√2 后，若再加 j(log ℓ)/ℓ+O(1/ℓ)，则精确解要求 j≤1/4。若 j=1/4 且有下一项 q/ℓ+o(1/ℓ)，则必须 q≤(1+log√2)/2。任一层严格低于阈值时，虽有趋于零的剩余质量，仍足以建立条件高斯极限并排除固定宽的远端高平台。[证明](../proofs/029-saturated-origin.md)

两个本机实现使用随参数移动的鞍点，避免直接相减巨大指数。主脚本以 75 位求积校准 j=−1、0、1；在 L=10²⁴、j=1 时，L(m−1)/log L 约为 0.737816，极限为 0.75。在 j=q=0 的独立复核中，扣去首项后的 L(1−m)−(log L)/4 为 0.6732867951399863，与 (1+log√2)/2 相合。代码与完整运行输出见 computation/round029_saturation.py、computation/round029/。这些结果检验系数，渐近余项和条件分布由证明控制。

第25–29轮两机协同计算中，MacBook 早期 CPU 与 GPU 批次的时间戳没有交叠。追加任务改由同一远程 shell 同时投放 15 个 CPU 工作进程和 Metal。已核对两者共同启动于 01:04:52 UTC，并在 GPU 设备利用率为 100% 时记录到在运行的本课题 CPU 工作者。本机重叠负载与设备计时已归档在第27轮。一般连续猜想及连续占满两个饱和阈值时的尾部结论仍开放。

联合扫描的 Metal 作业 35.573 秒命令时间，计算 292,172,100 个尾部偏移组合；其 45 次整机 GPU 采样均为 100%。同批 CPU 初版有 14/15 个分片在分支交界处触发数值断言，故未将其计入成功批次。原因是在远高斯尾上反演分位点时，舍入误差改变了接触判定。修正版以对数分布函数作 Newton 校正，独立 65 位求积核验见 computation/round029/validation_corner.json。初版与修正版均有保留，用于定位这个有限精度差异。上述 GPU 和 CPU 尾部扫描仅用于验证有限参数模型。
